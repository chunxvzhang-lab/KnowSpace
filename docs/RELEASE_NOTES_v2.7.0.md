# KnowSpace v2.7.0

**没有新功能，没有格式变化 —— 但这个版本决定了之后每一个版本的速度。**

这是 KnowSpace 的架构减负版：把四个巨石组件、十一个巨型服务拆开，把"写在文档里靠人遵守的规则"
变成"机器强制执行的门禁"。**没有改变任何既有文件格式**：`.md`、`.canvas`、`.mindmap.md`、
伴生文件与 `.xmind` 都与 v2.6.5 完全一致，升级不需要迁移，用户可见行为逐一对齐。

---

## 🏗️ 架构减负：代码从"能改"变成"敢改"

此前最大的四个文件分别是 `App.tsx`（2,349 行）、`CanvasView.tsx`（7,179 行）、
`MindmapView.tsx`（3,586 行）与一批千行服务 —— 改动半径不可控，是后续性能与 AI 能力的硬阻塞。

- **`App.tsx` 2,349 → 776 行**：未保存守卫、标签页操作、双链导航、重命名、文档创作、
  阅读位置持久化、章节加载各自成域；外壳 chrome（活动栏 / 工具栏 / 目录栏）独立成组件。
- **白板 7,179 → 932 行组合根**：文档 / 历史 / 相机 / 选区 / 拖拽 / 连接 / 指针复用 /
  CRUD / 边操作 / 媒体剪贴板 / 演示 / 快捷键 / 右键菜单 / 导出建议共 14 个域 hook，
  加节点层、世界层、工具栏、覆盖层、演示 chrome 等视图组件 —— 每个文件只有一件事。
- **思维导图 3,586 → 773 行**：同样的 9-hook + 2-组件布局；sidecar（伴生文件）的
  加载合并与防抖保存契约原样保留，由 110 项测试逐条钉住。
- **超千行文件 15 → 0**，11 个巨型服务（fsrs / markdown / canvas 三件套 / mindmap 三件套等）
  全部收敛到 800 行内，对外导入面逐字节不变，golden 快照坐标级一致。

## ⌨️ 命令总线：一个动作，一处注册

命令面板（`>`）、全局快捷键、系统菜单此前各写一份动作表 —— 同一个"切换视图"最多被接线 5 次，
其中思维导图与目录侧栏的切换是两份逐字复制、打字机开关是两个分叉实现。现在：
`core/commands.ts` 是唯一注册表，处理器在应用壳绑定一次，三个入口全部走 `execute(id)`；
即将上线的插件体系与 AI 指令将复用同一条总线。

## 🧱 IPC 网关：五个命名空间与一次版本握手

渲染层 60+ 个扁平方法收敛为 `files` / `history` / `media` / `system` / `capture` 五个命名空间，
带 `apiVersion`；主进程 handler 从 2,405 行的 `main.cjs` 拆为按域模块（lifecycle 归 lifecycle）。
58 条通道与三端类型声明由一份契约守卫测试双向钉住 —— 任何一端改名、漏注册、多出死通道都会立刻变红。

## 🛡️ 质量门禁：从"记得跑"变成"漏不掉"

本仓库的规则文档极好，但它们靠人执行 —— 测试基线曾带着 v2.6.4 的数字发布了 v2.6.5，而且无人察觉。
这一版把门禁搬进机器：

| 闸门 | 时机 | 内容 |
| --- | --- | --- |
| pre-commit | 每次提交 | 暂存文件 ESLint + Prettier（秒级） |
| commit-msg | 每次提交 | Conventional Commits 强制（提交信息是工程记录） |
| pre-push | 每次推送 | 全量 typecheck |
| CI / `preflight` | 每次 PR / 每次发版 | typecheck → lint → format → **质量棘轮** → 全量测试 → **基线比对** |

**质量棘轮**（`docs/QUALITY_BASELINE.md`，脚本生成、禁止手改）：类型逃逸次数、超千行文件数、
最大文件行数——只许变好，不许变坏。它不要求"清零"，只要求"不比昨天差"，所以每次改动都必然可达。

## ✂️ 顺带修掉的交互边界

- 思维导图「换到另一侧」弹层出现后按 `Esc`：现在正确关闭弹层，而不是把弹层留在原地、
  反而清空了节点选择。
- 全局快捷键处理器对以 `window` 为目标的事件不再可能崩溃（此前整条快捷键链会被一次
  合成事件击穿）。

## 🧪 零回归证明

**113 个测试套件、1,414 项**单元与集成测试零失败；每一次搬迁都发生在全量绿之后、独立可回滚
的提交之内。重构期间发现并修复的三个潜在回归（最后一张标签关闭后重开同文档的空白态、
快捷键 effect 的一处陈旧闭包、两处绕过类型检查的桥接断言）在合并前均已回归测试化。

## 升级说明

- 直接安装即可（安装包 / 便携版同版本号）。用户数据与文件格式零变化，无需任何迁移。
- 本版本是工程能力计划（`docs/ENGINEERING_CAPABILITY_PLAN.md`）阶段 0 + 阶段 1 的落地；
  下一阶段（v2.8.0）将基于此架构做性能与资源：长文 AST Worker 化、预览 DOM 虚拟化、
  多标签冷冻。
