## 📈 Mermaid 图表首屏大幅提速

先看剖面上说的是什么：用新的诊断车道把 30 图语料的首屏成本拆开，发现
**第一张图 ~420ms、之后每张仅 ~50-140ms**——大头不是图表加载（Mermaid 模块
自页面加载起就常驻内存），而是引擎**一次性的初始化**（主题编译、布局系统、
渲染器构造）。

现在，应用在启动后的空闲窗口预先画一张会立即丢弃的哑图，把这次初始化付掉。
真实使用节奏（打开应用后浏览片刻，再打开一篇含图文档）下实测：

| 场景 | v2.7.4 | v2.7.5 |
| --- | ---: | ---: |
| 首图出现（预先生效节奏，两轮实测） | 421 ms | **121-123 ms** |
| 后续每张边际 | 50-140 ms | 不变 |

两个不更差的保证：如果你打开文档快过空闲窗口，正式渲染会排队等预热完成
（成本与旧版首图等同，不会叠加）；预热本身失败则完全免费——首图照旧走冷路径。

## 🧪 复盘面板偶发失败根治

每日复盘面板在全量测试下偶发失败（历史上换过三副面孔）：分块解析每 8ms
让渡一次渲染线程，满载机器上哪怕 3 篇笔记也会跨帧——首屏短暂停在加载态，
谁先查询卡片谁输掉竞态；负向断言还会在加载态下"空满足"。现在解析的分片
粒度成了测试接缝（产品默认 8ms 不变），面板套件在测试里一次解析完成，
39 个用例的首屏在任何机器负载下都确定就绪。

## ⚙️ 工程：一键发布编排

人写——脚本只检查它在不在、版本号对不对。
