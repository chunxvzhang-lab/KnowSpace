# KnowSpace v2.7.8

**知识图谱：四个被实测出来的性能瓶颈，以及画布不再自我重建。**

v2.7.7 之后的功能优化版：把知识图谱模块的显示效果、加载速度与交互流畅度按"先量后改"的方式重做了一遍。四个瓶颈里有三个不在最初的猜想里——构建阶段的路径扫描、每次数据变化都销毁重建的 Cytoscape 实例、以及 `cy.fit()` 的包围盒遍历，全都是靠剖析器和浏览器埋点找出来的，不是靠读代码猜的。**既有文件格式一律不变**（`.md`、`.canvas`、`.mindmap.md`、伴生文件与 `.xmind` 与 v2.7.7 完全一致，升级不需要迁移）。

---

## ⚡ 性能：四个瓶颈，逐个实测

- **构建阶段：8,000 节点 2,568ms → 119ms（21.6×）**。CPU 剖析显示构建耗时 **94.8%** 卡在节点去重里的一处路径别名全表扫描（对每个候选节点遍历整张别名表，O(n²)）。换成保序的后缀索引：仍然返回原扫描会返回的**最早注册**的匹配，也仍然保留原来裸 `endsWith` 的匹配行为——把判据"顺手修正"成按路径段对齐会**悄悄改变哪些文档被去重**，那是数据变化而非性能优化。用 200 个随机仓库对照原算法逐字节比对，结果完全一致。

- **布局：3,200 节点 10,414ms → 1,102ms（9.4×）**。力导向的斥力计算原本是 O(n²×迭代)，且同步跑在 Cytoscape 初始化里——3,200 节点会**冻结整个应用**十秒，不只是图谱分栏。现在 192 节点以上走 Barnes-Hut 四叉树近似，阈值以下仍是原暴力循环（逐位一致）。共位节点的抖动也从 `Math.random()` 改为确定性函数：同一张图每次布局结果相同，不再出现"关掉筛选再打开、节点位置就变了"。迭代次数在 400 节点以上按曲线收敛到 45 次——实测这是拐点，布局时间减半而节点间距仍远高于圆点开始相碰的约 20px。

- **交互：拖拽帧率 p50 200ms → 16.7ms，掉帧 69 → 6（1,200 节点）**。原先每次数据变化都会**销毁并重建整个 Cytoscape 实例**。用画布身份计数实测：每次筛选切换产生 3 个全新画布元素；约 1,100 节点下"销毁+重建"占一次筛选点击 ~1,200ms 中的 **485ms**，而同样一次元素交换在存活实例上只要 **16ms**。现在实例只创建一次、数据原地更新（元素走 `cy.json`、配色走 `cy.style`），筛选与主题切换都不再产生新画布。

- **视口拟合：618ms → 35ms**。`cy.fit()` 是数据交换路径里最贵的单项（约占 ~900ms 长任务中的 620ms），其中 `elements().boundingBox()` 就占 ~180ms——它要遍历每个元素并测量其渲染范围（含标签文字），而 `fit` 内部又走了一遍。布局坐标本来就在手上，于是改为纯算术拟合，不再做元素测量。

## 🎨 显示：两处纠正

- **浅色主题节点配色此前不达可见门槛**。实测普通文档节点在白色画布上只有 **2.56:1**、闪念节点 **2.15:1**，都低于 WCAG 非文字元素 3:1；两者肉眼"看着还行"、截图也看不出来，只有算比值才发现。现在分别为 **4.76:1** 与 **3.19:1**，并保留"当前文档 > 普通文档 > 闪念"的视觉层级（由测试钉住，防止后续改色把层级压平）。

- **缩放时隐藏过小的标签**。缩得很小时每个标签只有几个像素高，既不可读又每帧都要为每个节点做一次文字排版。现在渲染高度低于 7px 的标签直接不画；**悬停节点与高亮邻域豁免**，否则这个阈值会变成单向门——在最需要知道"这个点是什么"的缩放级别上，悬停反而什么也不显示。

## 🚀 加载与交互

- **搜索框防抖 180ms**。原先每敲一个键都会重建整张图（`filteredData` 是重建路径的唯一依赖），在 800 节点上是每次按键约 405ms 的同步布局，输入明显滞后于光标。输入框自身的值仍然即时，两者不一致期间表头显示"筛选中"提示。

- **默认 1,500 节点上限**。按连接度排序取前 N，当前文档始终保留，同一仓库每次得到同一子集（确定性）。这是**降级而非静默截断**：表头明确写出"已省略 N"，筛选面板提供开关可显示全部节点。

- **图谱数据改用 `useDeferredValue`**。后台索引每处理一批文档就会替换 `backlinkIndex`，此前这会让图谱（连同实例）在用户眼前重建一次又一批。

- **局部图谱的点击回调改走 ref**。它原本是 `BacklinksPanel` 里传入的内联箭头函数，导致该面板任何一次重渲染都会拆掉局部图谱并重跑布局。

## 测试

**143 个测试套件、1,691 项**单元与集成测试（1,689 通过、2 项基准默认跳过），零回归。本版新增 26 项守卫，专门钉住上面那些"等价性"：路径别名索引对照原算法在 200 个随机仓库上逐字节一致、Barnes-Hut 在阈值下与暴力循环逐位一致、节点上限的确定性与边一致性、视口拟合不让节点越界、浅色配色的对比度与层级、以及布局迭代预算的拐点。

浏览器端回归验证：主题切换（墨水屏 ↔ 浅色）、窗口缩放、缩放控件与重置拟合之后图谱均正常渲染，无页面报错。

**诚实说明**：筛选点击剩余约 550ms 的长任务发生在本模块之外——React 提交与 Cytoscape 对约 4,400 个元素的内部样式重算。继续压需要改 Cytoscape 内部或减少渲染元素数，两者都不属于本次改动范围。
