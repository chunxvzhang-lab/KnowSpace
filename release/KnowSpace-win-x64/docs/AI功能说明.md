# KnowSpace AI 一期使用与开发说明

一期提供桌面端模型连接、对话修改与创作、知识问答、选区写作、大纲全文写作和资料汇总。模型由用户自行配置，AI 工作台按需加载。

## 对话修改：直接操作当前文档

在「对话创作」输入“文件一级标题改为测试”，AI 助理会返回精确修改，应用在当前原文中执行替换，保留未要求修改的内容。修改前后的内容可在「查看修改内容」中核对，也可以撤销本次写入。

修改采用唯一原文匹配，不会把“修订说明”追加进正文。输出格式无效、匹配不到、出现多处相同片段、修改范围重叠或生成期间文档变化时，均拒绝写入。需要更精确时，请明确指定段落，或使用「选区写作」。单次修改读取完整原文，上限 20000 字符；超过上限请选区修改，不截取部分原文后覆盖全文。

「上下文与写入选项」默认收起，展开后可手动选择“修改当前文档”、指定新内容插入位置或关闭自动写入。

## 对话创作：正文、脑图与白板

点击「AI 助理」默认进入「对话创作」。输入“补充项目实施步骤”“整理成思维导图”或“生成 5 张白板卡片”，助手会识别输出形式；也可在「生成内容」中手动选择。

- 正文：生成后追加到当前 Markdown 文档末尾；可选择生成时的光标位置，不替换原文。
- 思维导图：输出 Markdown 标题与嵌套列表，追加后自动打开脑图视图，节点可以继续编辑。
- 白板卡片：在当前 `.canvas` 白板中追加可编辑文本卡片并自动排布；当前为 Markdown 时打开新白板保存流程，原文保留。单次 1–24 张卡片。

已有脑图和卡片也可直接通过对话修改。例如：“把准备阶段重命名为需求分析，在其下新增访谈记录子节点”“将预算卡片的10万元改为20万元”“删除周期卡片”。修改指令使用精确替换，不会再次追加整张脑图或重复卡片，并保留当前视图。新增脑图会匹配当前文档的标题或列表结构，确保分支可见。

白板修改按原始节点 ID 定位，只操作文本卡片内容，保留节点位置、尺寸、颜色、其他节点与连线；删除整张卡片会同时删除与它相连的边。同名卡片应提供区别信息，也可在发送内容预览中查看节点 ID。找不到目标、原文不唯一或输出格式不正确时拒绝写入。另存修改结果时仍保存为 `.canvas`。本期不通过 AI 移动卡片、调整尺寸或修改非文本节点。

手动编辑脑图后，先点击“同步到文档”；正在编辑的卡片先完成编辑。存在未提交的局部修改时，AI 写入会被阻止，防止使用旧原文覆盖新改动。精确修改读取完整文档或完整白板 JSON，上限 20000 字符，超过上限需缩小内容。删除最后一张卡片后白板保持为空，重新打开不会自动补卡。

默认勾选「生成完成后直接写入」。取消勾选可先修改草稿，再点击「写入当前文档」或另存为新文件。写入使用现有文档会话和自动保存设置，仍受保存失败与磁盘版本冲突检查保护。白板与新笔记使用同一套新建文件流程，包括未保存内容的提示。

生成期间若文档内容被修改或切换，不自动写入，生成结果保留为草稿。「撤销本次写入」仅在写入后文档没有其他修改时恢复此前内容，避免撤销覆盖后续编辑。停止、超时、输出截断或卡片格式不合法时不会写入。空白文档可根据对话创作；最多发送当前文档开头 12000 字符和最近两轮简短对话。需要完整大纲写作时仍使用「选区写作 → 按大纲写全文」。

## 启动与入口

开发工作区中安装依赖后，运行中文生产构建并启动桌面应用：

```powershell
$env:KNOWSPACE_LANGUAGE='zh'
npm run build
npm run desktop
```

默认构建语言沿用项目现有设置；未设置 `KNOWSPACE_LANGUAGE=zh` 时构建英文界面。

打开 Markdown 笔记，点击左侧「AI 助理」。也可通过命令面板中的 AI 命令、编辑器选区右键菜单，或 `/AI问答`、`/AI摘要` 进入。模型接口统一在「关于应用 → 模型接口」中配置；AI 助理右上方的「模型接口」可直接打开该页。浏览器页面不能直接使用桌面 AI 桥接。

AI 助理固定在工作区右侧，与正文并排，不覆盖笔记；收起后正文恢复可用宽度。窗口较窄时会暂时隐藏目录或大纲以保留阅读空间，不修改已保存的侧栏偏好。小于 720px 时正文与助手上下排列，仍可同时查看与滚动。助手的任务和来源区可独立滚动，输入框始终位于助手底部。

## 连接模型

点击左侧「关于应用」，切换到「模型接口」。填写并保存后，AI 助理自动刷新所用配置，不必关闭当前文档。

| 接口协议 | 服务地址 | 模型名称 |
|---|---|---|
| OpenAI 兼容 API | 填服务商提供的 API 根地址，例如 `https://your-provider.example/v1` | 填服务商实际支持的模型 ID |
| 本地 Ollama | 默认 `http://127.0.0.1:11434` | 填本机已安装的模型名称 |

兼容协议向根地址追加 `/chat/completions`；Ollama 追加 `/api/chat`。请勿填写完整的聊天接口路径。远程地址要求 HTTPS，本机回环地址允许 HTTP。地址中不能包含凭证、查询参数或片段；请求不会跟随重定向。

填写 API Key 后点击「保存并测试连接」。连接测试只发送简短测试消息，可能产生少量用量；不发送笔记。测试验证文字流式接口，不能证明模型回答质量，也不代表已验证该服务的全部能力。

凭证通过 Electron 主进程使用系统安全存储加密。系统加密不可用时可主动勾选「新凭证仅在本次应用会话保存」，退出应用后失效。界面转交凭证后清空输入框；后续读取配置只返回是否存在凭证。更换服务地址或协议会清除原凭证。

## 知识问答与来源

1. 在「工作台」选择「知识问答」。
2. 展开「上下文与写入选项」，选择当前文档、最多 8 篇笔记、指定目录或当前知识库。
3. 输入问题，点击「预览发送内容」，核对来源卡片。
4. 点击「生成」。生成过程中可以停止，已收到文字保留为未完成草稿。
5. 点击 `[S1]` 等来源卡片，使用现有文档导航跳转原文。来源已变化时显示提示。

当前文档使用编辑器中的未保存内容。其他笔记依赖现有索引；空文档、尚未索引或读取失败的笔记会显示覆盖不足提示。隐藏笔记和白板文件不进入范围检索。选定目录同时包含其子目录。

上下文最多 8 个片段、合计 20000 字符，每个常规片段最多 6000 字符。长文会采样段落，并明确提示尚未完整阅读。检索复用现有关键词与结构化索引；本期没有向量语义召回。问答最多携带最近两轮简短对话；新对话会清空临时上下文。

引用检查会提示缺失或不存在的引用标号。标号合法并不保证结论得到原文支持，仍需核对来源。

## 选区写作

在可编辑的 Markdown 文档中选中文字，选择「选区写作」，填写润色、压缩或翻译等要求后生成。工作台提供原选区与可编辑的改写草稿，对照后点击「应用到选区」。

应用前同时检查文档身份、版本与编辑器全文。生成期间发生编辑或切换文档时，旧提案不能应用，草稿保留供复制或重新生成。应用通过现有 CodeMirror 编辑事务完成，可一次撤销；不会直接覆盖磁盘文件。选区上限为 12000 字符。

## 按 Markdown 大纲写全文

1. 打开现有 `.md` / `.markdown` 文档，或新建 Markdown 笔记。用 `#` 至 `######` 写标题大纲，可在标题下保留已有事实、要点和写作约束。
2. 打开右侧AI 助理，选择「选区写作」，展开「上下文与写入选项」，将「写作方式」切换为「按大纲写全文」。此方式不需要选中文字；标题列表用于核对整篇结构。
3. 在底部填写文章用途、受众、语气和篇幅等要求。点击「预览发送内容」，可检查完整的大纲与正文，此时不调用模型。
4. 点击「生成全文」。助手一次发送当前文档的完整未保存内容，要求模型按标题顺序逐章扩写，保留已有事实、格式及 YAML 元数据，对未知信息标注待确认。
5. 在「全文草稿」中审核并编辑结果。点击「替换当前文档全文」，再点击「确认替换全文」；「保留原文」可取消本次替换。若当前处于阅读模式，先点击「进入实时预览编辑」。
6. 应用后可在正文编辑器中按 `Ctrl+Z` 一次撤销。保存遵循「关于应用」中的自动保存设置：开启时停止编辑约 1.5 秒后写入磁盘；关闭时按 `Ctrl+S` 保存；也可直接「保存为新笔记」，另存纯 Markdown 全文。

示例大纲：

```markdown
# 知识库建设方案

## 建设背景
已知要点：用于内部知识整理。

## 建设目标
### 使用场景

## 实施计划

## 验收安排
```

该方式完整读取单篇文档，输入上限 20000 字符；超限会拒绝，不会采样或截掉末尾章节。代码围栏、引用和 YAML 中的伪标题不计入大纲。标题采用 `#` 语法，与应用的 Markdown 渲染方式保持一致。

采纳前会核对标题文字、层级、顺序、末级空章节和原 YAML 元数据；存在不一致时禁用全文替换，仍可编辑草稿。该检查不代替事实核查，也无法判断所有正文论证是否充分。生成后修改过原文或切换了文档时，旧草稿无法覆盖当前正文。

单次输出沿用「模型连接」中的输出 Token 上限（最高 8192），不会自动提高用量设置。长文章可能超过模型输出上限；兼容 API 和 Ollama 报告长度截断时，文字保留为未完成草稿，不能直接应用。可自行提高输出上限或缩小任务范围。本期未实现自动分章续写、多次请求拼接或跨文档写作。

## 资料汇总

选择「资料汇总」，指定最多 8 篇笔记，输入所需成果结构，例如「整理结论、决策依据、分歧和待确认事项」。宿主按固定范围检索与采样资料，将实际来源交给模型生成草稿。

完成后可「保存为新笔记」。保存复用现有新建流程与未保存内容保护，并将回答、模型信息和原文摘录一并写入 Markdown。界面显示「已发起保存」表示保存流程已打开；若取消原生保存对话框，可点击「重新保存」。

本期智能体是有界的资料汇总流程，使用一次模型生成请求；没有开放任意工具调用、终端命令、联网搜索、后台自主执行或多文件修改。

## 用量、记录与失败处理

- 每个窗口最多一个活动请求，主进程全局最多三个，单次超时 120 秒。
- 每次请求先以输入 UTF-8 字节数、输出上限和固定余量保守预留本机日预算。服务报告输入、输出 Token 时按报告值校正；未报告、失败或停止时保留预留，避免漏计已可能发生的用量。
- 本机预算按本地日历日重置，不等同于服务商账单，也不能限制其他程序的费用。
- 对话默认不落盘。主动开启记录后，每库保留最近 20 条完成记录，最多保留 20 个库；记录包含来源摘录。失败或取消的草稿不会进入完成记录。
- 「记录」中可以清空当前库历史及面板中的来源缓存。关闭记录保存不会自动删除旧记录，需要时主动清空。
- 配置和记录位于 Electron `userData/ai/`，不存入原始知识库或安装目录。
- 401、403、404、429、网络错误、超时、畸形流和提前中断会明确报错。兼容协议要求结束标记，Ollama 要求 `done:true`；不完整响应保留为草稿。不会因本地服务失败自动转发到云端。

## 实现位置与验证

| 模块 | 职责 |
|---|---|
| `electron/ai-provider.cjs` | 协议、请求校验、流式解析、取消和用量 |
| `electron/ai-store.cjs` | 系统加密凭证、串行配置写入、预算及本地记录 |
| `electron/ai.cjs` | 可信窗口 IPC、并发与请求生命周期 |
| `src/services/aiContext.ts` | 范围检索、来源、消息、版本绑定与可撤销应用 |
| `src/components/ai/` | 工作台、来源预览、模型设置及结果采纳 |
| `scripts/verify-ai-phase1.cjs` | 隔离资料和用户配置下的真实 Electron 验收 |
| `scripts/verify-ai-authoring.cjs` | 确定性桌面回归：脑图及卡片生成、修改、删除、撤销、重开、空内容与冲突保护 |
| `scripts/verify-ai-real-diagrams.cjs` | 使用已有模型配置和虚构文档，验证脑图与白板连续生成及修改 |

单元测试覆盖本机 HTTP 流、Ollama/兼容协议、异常响应、取消、凭证和预算、范围隔离、未保存内容、选区冲突、大纲完整性、全文应用、一次撤销及 IPC 窗口归属。桌面验收使用本机确定性测试服务，测试 UI、IPC 与原生文件创建流程，不调用商业模型。

本期验收目标为 Windows。已用本机配置的模型和虚构文档实测脑图与卡片生成及修改；这不代表所有模型或所有指令均已验证。本地 Ollama 实例、引用支撑度、真实计费和其他操作系统，仍需在相应服务与硬件环境中另外验证。生产构建不会自动更新已有的便携版 EXE。
